# Rule 01: Core Philosophy & Resolution Retention

## 1. コア原則: "Stop Re-deriving, Start Compiling"
- 従来の RAG のように未構造化ドキュメントを都度断片的に検索・再解釈するのではなく、**AI エージェント自身が継続的に整理・統合・相互リンク・検証・減衰管理した構造化ナレッジ層（Compiled Knowledge Layer）** を Git 上で蓄積・成長させる。
- 「一度整理した知識は二度と再導出させない」状態を維持する。

## 2. 解像度の完全保持（Zero Information Loss）
- **最優先義務**: 一次資料（Excel, PDF, Word, SQL 等）に記載されている詳細仕様を「箇条書き3行にまとめる」などの要約省略を絶対に行わない。
  - **DB テーブル定義**: すべてのカラム名、物理名、論理名、データ型、桁数、NULL 可否、デフォルト値、PK/FK、インデックス、備考を 100% 保持。
  - **API 仕様**: エンドポイント URL、HTTP メソッド、リクエストヘッダ、クエリパラメータ、リクエストボディ（JSON スキーマ）、レスポンス定義（ステータスコード別）、エラーコード一覧を 100% 保持。
  - **業務ロジック / 計算式**: 条件分岐、計算式、バリデーション条件、例外処理を省略せず数式・表・コードブロックで記載。

## 3. 1 Concept = 1 File 原則
- 1 つの大きな資料をそのまま巨大な 1 ファイルにせず、「1 概念 = 1 ファイル」の粒度で論理的に分割する（例: 1 テーブル = 1 ファイル、1 API = 1 ファイル、1 画面 = 1 ファイル、1 要件 = 1 ファイル）。
- 関連する概念同士は Markdown リンク（`[リンク名](../path/to/concept.md)`）で相互接続する。

## 4. 機密情報のスクラビング (Privacy & Secret Protection)
- 一次資料に含まれる以下の機密情報は、Wiki への登録時に必ず自動マスクまたは環境変数化する：
  - API キー、シークレットトークン、パスワード、暗号化キー（例: `$ENV:AUTH_SECRET` または `***MASKED***`）
  - 個人情報（実在の顧客氏名、個人メールアドレス、電話番号、クレジットカード番号等）
- 接続先 DB ホスト名や内部 IP アドレスで本番環境固有のものは適宜ダミーまたは変数表記に置き換える。
