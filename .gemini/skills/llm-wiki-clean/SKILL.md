# LLM Wiki Clean Skill

このスキルは、`anydoc` や各種コンバーターによって変換された直後の Markdown ファイルからノイズを除去し、人間の可読性と AI エージェントの検索精度を最大化するクリーンな Markdown に整形します。

## 主な役割と解決する問題

1. **Excel 変換時の大量の空セル削除**:
   - `| | | | |` のように何列・何行も連続する空セル・空行を削除。
   - 全行で値が存在しない無駄な列のトリミング。
2. **結合セル・多段ヘッダーの再構成**:
   - Excel のセル結合により崩れた表ヘッダーを解釈し、標準的な Markdown 表（または定義リスト）に再構成。
3. **不要な改行・空白ゴミの除去**:
   - 連続する 3 つ以上の改行を 2 つに圧縮。
   - `<br>` タグの乱用や `&nbsp;` などの HTML 残骸の除去。
4. **情報の解像度保持（要約劣化の防止）**:
   - **【最重要】** API パラメータ一覧、テーブルカラム定義、エラーコード表、業務ルール等の詳細定義を「箇条書き 3 行に要約する」といった勝手な情報削除を行わず、元の解像度を完全に保つ。
5. **複数シートのセクション分離**:
   - 複数シートを持つブックを `## Sheet: <シート名>` 見出しで論理的に整理。

---

## 実行手順 (Execution Workflow)

### ステップ 1: ルールベース前処理（スクリプト実行）
まず、機械的な空行・空列の削減スクリプトを実行します。
```bash
python scripts/table_cleaner.py <対象ファイル.md> <整形先ファイル.md>
```

### ステップ 2: LLM による文脈理解と構造整形
前処理後の Markdown に対し、エージェントは以下のルールで最終整形を行います。

1. **見出しの階層化**:
   - 文書タイトルを `# 文書名`、大項目を `## 大項目`、小項目を `### 小項目` に設定。
2. **表の整形**:
   - 表が横に長すぎる場合や複雑すぎる場合は、項目ごとの「定義リスト（Markdown 箇条書き）」への変換を検討。
   - 表の各列の境界を綺麗に揃える。
3. **コード・SQL・パラメータの保護**:
   - SQL や DDL、JSON、コード片は必ず ` ```sql ` などのフェンスドコードブロックで囲む。
4. **未確定箇所の明記**:
   - 原本で欠落している値や「TBD」「要確認」と書かれている箇所は勝手に想像で埋めず、`要確認: [内容]` として明記する。

## 出力例 (Before & After)

### Before (変換直後の粗い Markdown)
```markdown
| No | 項目名 | | | 型 | | 必須 | 備考 | | |
|---|---|---|---|---|---|---|---|---|---|
| 1 | user_id | | | UUID | | ◯ | 主キー | | |
| 2 | email | | | VARCHAR | | ◯ | | | |
| | | | | | | | | | |
| | | | | | | | | | |
```

### After (llm-wiki-clean 整形後)
```markdown
# ユーザーテーブル定義

| No | 項目名 | 型 | 必須 | 備考 |
| :--- | :--- | :--- | :---: | :--- |
| 1 | `user_id` | UUID | ◯ | 主キー (UUID v4) |
| 2 | `email` | VARCHAR(255) | ◯ | ログイン用メールアドレス |
```
