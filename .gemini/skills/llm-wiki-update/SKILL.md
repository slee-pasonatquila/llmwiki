# LLM Wiki Update Skill

このスキルは、プロジェクト進行中に発生する「仕様変更」「追加要望」「設計見直し」を LLM Wiki に反映し、知識の鮮度と変更履歴の透明性を維持します。

---

## 変更運用の規律 (Update Principles)

1. **破壊的削除の禁止（過去経緯の保持）**:
   - 変更前の記述を単に消し去るのではなく、変更理由が重要な箇所には取り消し線（`~~旧仕様~~`）を残し、直後に新仕様と変更日を記載します。
2. **アーキテクチャ・重要設計の決定記録 (ADR の起票)**:
   - データベース変更や認証方式の変更など、大きなアーキテクチャ上の決定は `wiki/05_decisions/` 配下に新規 ADR（例: `adr_001_jwt_auth.md`）として起票します。
3. **関連ドキュメントの連鎖更新**:
   - 要件が変わった場合、紐づく「詳細設計」「API 定義」「DB スキーマ」の関連記述も忘れずに更新します。
4. **`log.md` の記録**:
   - `wiki/log.md` の先頭に、変更内容と影響を受けたドキュメントへのリンクを追記します。

---

## 更新作業の流れ

```text
[仕様変更の発生]
       │
       ▼
1. 影響箇所の特定 (wiki/index.md および cross-link の探索)
       │
       ▼
2. Concept ドキュメントの編集 (取り消し線 + 新仕様の追記 + timestamp更新)
       │
       ▼
3. 必要に応じて ADR の新規作成 (wiki/05_decisions/adr_xxx.md)
       │
       ▼
4. wiki/log.md および index.md の更新
       │
       ▼
5. python scripts/lint_okf.py による整合性確認
```
